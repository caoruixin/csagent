## 1 项目概述

### 1.1 背景与期望

在 Enhanced Chat 已存在的前提下，引入与 **Salesforce 深度集成**的聊天机器人作为**首触达**，通过引导式对话、知识内容展示与简单支持动作，提升自助解决率；无法解决时**无缝转人工**并传递上下文，减少重复沟通、加快解决。

- **渠道底座**：Gumtree 官网已部署 **Salesforce Enhanced Chat**（含现有人工服务模式）。  
- **智能客服形态**：在 Enhanced Chat **同一会话线程**内，增加**自定义 Chat Bot**。  
- **一期能力边界**：Bot **以 FAQ 自助为主**（向量检索  可选结构化引导）；复杂动作、开放式生成回答、非 FAQ 类自动化**不在一期必选范围**。  
- **人机协作**：支持 **Bot ↔ 人工** 互转（用户显式转人工、自动升级条件、坐席侧必要时切回 Bot 或结束 Bot 轮次——以产品最终规则为准），并与 **Case 创建、Omni-Channel、Knowledge** 打通。  
- **知识来源与向量库**：一期设计 **FAQ 专用向量库**；主数据来自 **Salesforce Knowledge**（与 Help Centre 一致的事实源）；**可选**自 **全站 Git 仓库**（文档/Markdown/配置说明等）增量构建索引，用于内部技术 FAQ 或运营文档类问答（需合规与内容治理审批）。

### 1.2 业务现状摘要

- **客户侧**：Help Centre 可解决大量问题，但自助未在恰当时机呈现，客户倾向直接找人工或其他渠道投诉。  
- **内部侧**：约 **5.7k 次/月** 聊天量，约 **4.1 FTE** 产能消耗（2 会话并发、80% 占用、30% shrinkage），重复性、低复杂度问题占用坐席时间，影响高峰等待与复杂案件处理。  
- 考虑Email Case接入可行性。

### 1.3 主要联系原因


| 主题方向（归纳）                           | 说明                           |
| ---------------------------------- | ---------------------------- |
| Data Deletion / TMX / Blacklist 相关 | 高占比删除、过滤、纠正类诉求               |
| 登录 / 邮箱 / 密码                       | 账户访问类                        |
| Listing 可见性 /「我的广告在哪」/ 发布流程        | 广告与展示类                       |
| 非技术类广告数据咨询                         | 统计、展示等非技术问题                  |
| 其他高频单点                             | 以报表与 Contact Reason 月度数据为准迭代 |


### 1.4 成功指标


| 指标        | 说明                | 方向                 |
| --------- | ----------------- | ------------------ |
| **AI解决率** | Bot 内完成且未转人工的会话占比 | 国内业务70%            |
| **转人工率**  | 转人工占比及原因分布        | 可接受区间依赖业务复杂度，需分意图看 |
| **AI参评数** | 下发并参与客户数          | 宜 80%–90% 或与人工持平   |
| **AI参评率** | 占所有下发比例           | 7%                 |
| **AI满意度** | 满意占比              | 40%-70%            |




### 1.5 Bot解决的具体定义


| 定义     | 含义                                           | 粗算占比                                                                  |
| ------ | -------------------------------------------- | --------------------------------------------------------------------- |
| **D1** | **完全自动结案**（无人工）：仅靠知识库 自助链接，用户24小时相同问题不再重复进线  | 通常 **约 10%～25%**；技术、GDPR、申诉会显著拉低                                      |
| **D2** | **首解 / 显著减负**：用户获得正确下一步（状态说明、链接、表单），部分线下自助完成 | 将一期覆盖的 **A–E、F、F′ 话术类** 纳入，约 **45%～55%** 工单可被 Bot **有效承接或分流**（不等同全自动） |

#### 1.6.2.1 一期类别 A–F′：对话处理流程（交流路径）

**通用节点（所有 A–F′ 复用）**


| 步骤      | 行为                                                                         | 数据/报表                            |
| ------- | -------------------------------------------------------------------------- | -------------------------------- |
| G0 入口   | 菜单主题或自由文本 → 意图 + 置信度；低置信度时展示 **澄清按钮**（2 轮内）                                | 记录 `INTENT`、`intent_confidence`  |
| G1 检索   | FAQ 向量检索 +（可选）Knowledge 校验；低于阈值 → 澄清或 `faq_miss` 计数                        | `FAQ_SEARCH`、`chunk_ids`         |
| G2 回复   | **标题 + 1–3 句摘要 + 可点击链接**（F-KN-01）；禁止纯「请自行搜索」                               | `ARTICLE_SHOWN`                  |
| G3 解决确认 | 「是否解决？」→ **已解决**：感谢/结束（Containment）；**未解决**：更深检索 **1 次** 或提供 **转人工**       | `RESOLUTION_ASK`                 |
| G4 升级   | 用户显式转人工、自动升级条件（见 F-ES-02）、`faq_miss ≥ 2`                                   | `ESCALATION`、`escalation_reason` |
| G5 交接   | 写 `primary_intent`、`articles_shown`、`transcript_ref`、已有 `Case Id`（F-HO-01） | 随转人工 API                         |

**A — 帖子/广告状态与可见性**

## 2 系统角色

### 2.1 End User（客户）

- 通过Gumtree help centre **Enhanced Chat** 发起会话。  
- 与 **Bot** 或 **人工坐席** 在同一聊天线程中收发消息。  
- 可随时使用「转人工」或等价入口；在 FAQ 展示后可反馈「是否解决」。

### 2.2 Custom Chat Bot（自研 Bot 服务）

**3.2.1 无独立 C 端聊天 UI**（嵌入在 Enhanced Chat 体验中）。  
3.2.2 一期职责：**FAQ 意图识别 / 检索增强回答**、**解决确认**、**触发 Case 创建（按规则）**、**请求转人工并附带上下文**。  
3.2.3通过后端 API 与 **向量检索服务**、**Salesforce（Knowledge / Case / Messaging / Omni）** 交互。

### 2.3 Human Agent（人工客服）

- 在 **Service Console / Omni** 既有界面处理聊天。  
- 接收来自 Bot 的 **结构化上下文**（意图、置信度、关键槽位、已展示文章、Case Id、对话摘要或全文）。  
- 可在政策允许范围内使用内部工具；**一期不要求**坐席控制台内嵌「再调 Bot」按钮，但 PRD **预留**「会话状态：BOTACTIVE / HUMANACTIVE」以便二期扩展互转。

### 2.4 Salesforce Platform（Enhanced Chat  Service Cloud）

- 提供 **Messaging Session / Live Chat** 会话载体、**Omni-Channel** 路由、**Case**、**Knowledge**、**报表对象**。  
- 作为 **客户身份、队列、合规审计** 的系统记录权威来源（与现有配置一致）。

### 2.5 Knowledge & Content Ops（知识运营）

- 维护 **Salesforce Knowledge** 文章与 Help Centre 映射。  
- 审批 **Git 源** 是否进入向量库、版本与保留策略。

## 3 核心概念

### 3.1 Conversation / Messaging Session（会话载体）


| 概念                                                 | 说明                                                    |
| -------------------------------------------------- | ----------------------------------------------------- |
| **Salesforce Messaging Session**（或当前组织实际使用的聊天会话对象） | 客户与联系中心交互的**主键**；Bot 与人工共享**同一会话 ID**（或可追溯的关联 ID）。    |
| **Bot 轮次**                                         | 从会话开始到「转人工完成」或「会话关闭」前，由 Bot 处理的消息区间；需在自定义对象或事件日志中可统计。 |


### 3.2 Handling 状态机（逻辑状态，映射到实现）

与通用 IM 产品中的 `AI_HANDLING` / `HUMAN_HANDLING` 概念对齐，落地为 Salesforce 侧**可查询状态**（自定义字段或平台事件）。

```
                    用户进入聊天  
                          │  
                          ▼  
                ┌─────────────────┐  
                │  `BOT_HANDLING`   │ ◄── 默认：首触达为 Bot（受流量比例控制）  
                └────────┬────────┘  
                         │  
       ┌─────────────────┼─────────────────┐  
       │                 │                 │  
用户点击「转人工」   自动升级条件满足    `Bot` 解决并结束  
或关键词/按钮        （见 7.3）          （Containment）  
       │                 │                 │  
       ▼                 ▼                 ▼  
┌──────────────┐  ┌──────────────┐   ┌──────────┐  
│   `QUEUE_TO`   │  │   `QUEUE_TO`   │   │  `CLOSED`  │  
│   `HUMAN`      │  │   `HUMAN`      │   │ (可选)   │  
└──────┬───────┘  └──────┬───────┘   └──────────┘  
       │                 │  
       └────────┬────────┘  
                ▼  
        ┌───────────────┐  
        │ HUMAN\_HANDLING│  
        └───────┬───────┘  
                │  
     会话结束 `/` 超时 `/` 渠道关闭  
                ▼  
        ┌───────────────┐  
        │    `CLOSED`     │  
        └───────────────┘
```

**互转（二期可启用，一期文档化预留）**

- **Bot → 人工**：一期必做。  
- **人工 → Bot**：例如用户同意「由助手继续回答简单问题」时，将会话 handling 状态切回 `BOT_HANDLING` 并记录事件（**一期不做**）。

### 3.3 Message（消息）


| 属性    | 说明                                         |
| ----- | ------------------------------------------ |
| 发送方类型 | `USER` / `BOT` / `HUMAN_AGENT` / `SYSTEM`  |
| 归属    | 均属于同一会话；需在 transcript 中可区分来源以便报表与合规。       |
| 内容形态  | 一期 **纯文本** 为主，少量图片；链接类回复允许含 Knowledge URL。 |


### 3.4 FAQ 回答路径（一期核心）

1. **意图路由**（菜单选择  轻量 NLU）：将用户归到某一 FAQ 域或全局检索。
2. **向量检索**：在 **FAQ 向量库** 中召回 Top-K 片段 / Q-A 对。
3. **可选重排序**：Cross-encoder 或规则重排（视实现选型）。
4. **回复生成策略（保守）**：**一期优先模板化/摘录式回答**（直接引用 Knowledge 摘要  链接），避免无依据生成；若使用 LLM，仅允许在「严格 grounding」模式下组织语言，并记录引用来源 ID。

## 4 需求边界

### 4.1 范围内（Phase 1 · 必须）


| 编号      | 边界项               | 说明                                                                                                |
| ------- | ----------------- | ------------------------------------------------------------------------------------------------- |
| B-IN-01 | Web Enhanced Chat | 在 **Web** Enhanced Chat 流量范围内接入 Bot 首触达                                                           |
| B-IN-02 | 流量与试点             | 支持 **可配置流量比例**（如 10% / 50% / 100%）；未进入试点的流量行为与线上一致。                                               |
| B-IN-03 | 意图覆盖              | **5–10** 个高优先级意图；每个意图有关键字/菜单与 FAQ 映射。                                                             |
| B-IN-04 | FAQ 与知识           | **Salesforce Knowledge** 为对外事实源；Bot 返回**文章链接 短摘要**；展示后 **「是否解决」** 分支。                             |
| B-IN-05 | FAQ 向量库           | 建设 **独立 FAQ 向量索引**，支持语义检索与版本管理。                                                                   |
| B-IN-06 | 转人工               | 任意时刻可转人工；满足自动升级条件时转人工；转接话术含 **等待预期/下一步**。                                                         |
| B-IN-07 | 上下文交接             | 坐席可见：意图与置信度、结构化答案、**已展示 Knowledge 列表**、**Case Id（如有）**、**完整或摘要 transcript**（以性能与隐私评审为准）。          |
| B-IN-08 | Case 创建           | 对约定类别 **自动创建 Case**，必填字段齐全并按 **Omni 队列规则**路由。                                                     |
| B-IN-09 | 报表                | Containment、Escalation（含原因）、Drop-off、CSAT（若可采集）、高频意图与失败节点；数据落在 **Salesforce 可报表对象/字段** 或经许可的数仓同步。 |


### 4.2 范围内（Phase 1 · 可选 / 增强）


| 编号      | 边界项          | 说明                                                                  |
| ------- | ------------ | ------------------------------------------------------------------- |
| B-OP-01 | Git Repo 向量源 | 在治理审批前提下，从指定 **Git 仓库** 构建**第二索引**或**标签隔离的 collection**，用于内部文档类 FAQ |


### 4.3 范围外（本期不做）


| 编号       | 边界项                 | 说明                     |

| B-OUT-02 | 社交通道                | WhatsApp 等不在 Phase 1   |
| B-OUT-03 | 支付 / 退款 / 强身份自动化    | 不自动执行资金类或强验证类操作        |
| B-OUT-04 | 复杂纠纷 / 法律 / 欺诈自动裁决  | 必须转人工或固定话术指引。          |
| B-OUT-05 | 开放式闲聊与非 grounded 生成 | 一期不鼓励；检测到应引导至 FAQ 或人工。 |

### 5.2 与 Salesforce 的集成要点

- **消息入口**：采用经架构评审的接入方式（例如 Embedded Service 与自定义层、或 BYOC/Messaging API 组合），保证 **Bot 回复写回客户可见的同一聊天线程**。

- **Case**：通过 **REST/Composite** 或 **Apex REST** 创建；字段与队列规则与现有一致。  
- **Knowledge**：检索可并行 **Salesforce Knowledge API**（权威元数据、发布状态）与 **向量库**（语义召回）；**对外展示链接以 Knowledge URL 为准**。
