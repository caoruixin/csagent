- The 2 complex resolution-path Skill YAMLs (`resolve_faq_grounded_answer.yaml` + `resolve_intake_collect_and_handover.yaml`) per Sprint 37 freeze decision (e §6.2.5 + §6.2.6).

Layer: `prompt_projection` (RESOLVE Skill envelopes reach LLM via Skill-composed PhasePlan; same PhasePlan field set as pre-migration) + `semantic_planner` (LLM continues to own next-action / UC hypothesis / escalation posture / response strategy / customer-facing language; the migration relocates the source of teaching but does NOT shift LLM-owned decisions to Java per §1.3) + `skill_state` (SkillRegistry holds RESOLVE Skill definitions across requests; `SkillGuardrailDispatcher` resolves Skill `guardrails` at dispatch sites) + Runtime-owned grounding floor per §1.4 (S1 `must_cite_source` is a NEW Runtime-floor enforcement bounded per M2 §6 #4 verbatim authorization; the bounded inversion of `D-hard-citation-gate` is the principled exception, NOT a generic citation gate) + Runtime-owned capability floor per §1.4 (the 4 Sprint 39 guardrail types are all Runtime-floor enforcement, NOT LLM-owned semantic decisions).

## 2. Goal

Implement the Sprint 37 freeze decisions (e §6.2.5 + §6.2.6) + (g §8.2.1-§8.2.5) + (h §9) as runtime code, completing the SkillRegistry abstraction for ALL 6 phases. Post-Sprint-39, the 2 complex resolution phases (RESOLVE_FAQ + RESOLVE_INTAKE) compose PhasePlan from externalized Skill YAML via SkillRegistry (matching the 4 simpler phases Sprint 38 already migrated); the 3 scattered Sprint 6/7/11 predicates ship as declarative Skill `guardrails` enforced via the unified `SkillGuardrailDispatcher`; the NEW S1 `must_cite_source` predicate ships bounded per M2 §6 #4 verbatim authorization; the NEW S2 `intake_complete_required` declaration captures the existing Sprint 7 §I2 semantics in declarative form.
