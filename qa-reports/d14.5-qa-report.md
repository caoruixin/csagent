### Details

#### Issue 1: Double session save timing concern (MEDIUM)
- **File**: `server/src/main/java/com/gumtree/csagent/service/runtime/SessionManager.java:137-139`
- **Severity**: MEDIUM
- **Description**: The auto-search path saves the session before calling `controlKernel.processMessage()` (line 139), then saves it again at line 189 after the greeting is determined. Both saves happen inside the same `@Transactional` method, so both go to the same Hibernate session. This is correct for the intended purpose (ControlKernel needs the session persisted for turn recording). However, if `processMessage()` modifies session fields (which it does -- it increments `totalBotTurns`, changes `lastAction`, etc.), the second save at line 189 will persist those kernel-driven changes as part of session creation. This is likely intentional but should be documented.
- **Code**: Lines 137-142
- **Suggestion**: Add a comment explaining that ControlKernel-driven state changes (totalBotTurns, lastAction, etc.) are expected to be persisted by the second save. This avoids confusion for future maintainers.

#### Issue 2: Unsafe ObjectNode cast (MEDIUM)
- **File**: `server/src/main/java/com/gumtree/csagent/service/runtime/PhaseEvaluator.java:219-220`
- **Severity**: MEDIUM
- **Description**: The code casts `objectMapper.readTree(projection)` directly to `ObjectNode` without verifying the type. If `contextProjection.buildProjection()` ever returns a JSON array `[...]` or a scalar value, this cast will throw a `ClassCastException` that is caught by the outer try/catch and falls through to the hardcoded response. While the fallback is safe, the `ClassCastException` is misleading in logs -- it looks like a bug rather than a graceful degradation.
- **Code**: `(com.fasterxml.jackson.databind.node.ObjectNode) objectMapper.readTree(projection);`
- **Suggestion**: Add an explicit `instanceof` check: `JsonNode node = objectMapper.readTree(projection); if (!(node instanceof ObjectNode projNode)) { /* log and fall through */ }`.

#### Issue 3: Injection of unescaped form description into LLM instruction (MEDIUM)
- **File**: `server/src/main/java/com/gumtree/csagent/service/runtime/PhaseEvaluator.java:221-226`
- **Severity**: MEDIUM
- **Description**: The `formDescription` is embedded directly into the `faq_miss_instruction` string with single-quote wrapping: `"...the user described their issue in the pre-chat form: '" + formDescription + "'..."`. If the form description contains single quotes or special characters, it could break the instruction format or lead to prompt injection. The description has already been HTML-sanitized by `FormContextIngestionService.sanitize()`, but that sanitizer targets XSS (HTML tags), not JSON/prompt injection characters.
- **Code**: Line 223: `"...pre-chat form: '" + formDescription + "'..."`
- **Suggestion**: Escape or truncate the formDescription before embedding. At minimum, replace single quotes. Alternatively, inject it as a separate JSON field rather than inlining it in a natural-language instruction string.

#### Issue 4: Duplicated INTAKE_UCS constant (LOW)
- **File**: `SessionManager.java:28` and `PhaseEvaluator.java:26`
- **Severity**: LOW
- **Description**: Both `SessionManager` and `PhaseEvaluator` independently define `private static final Set<String> INTAKE_UCS = Set.of("UC-G", "UC-H", "UC-I", "UC-J", "UC-K")`. If the set of intake UCs changes, both files must be updated in sync.
- **Suggestion**: Extract to a shared location (e.g., a constant in `UseCaseRegistryService` or a dedicated `UseCaseConstants` class).

#### Issue 5: Thin wrapper method extractFormDescription (LOW)
- **File**: `server/src/main/java/com/gumtree/csagent/service/runtime/PhaseEvaluator.java:497-499`
- **Severity**: LOW
- **Description**: `extractFormDescription(session)` is a one-liner that calls `extractFormField(session, "description")`. It improves readability at the call site but adds an extra indirection layer.
- **Suggestion**: Keep as-is (readability benefit is worth the cost), but add a brief Javadoc explaining it is an intentional convenience wrapper.

#### Issue 6: Duplicated name fallback logic (LOW)
- **File**: `server/src/main/java/com/gumtree/csagent/service/runtime/SessionManager.java:144` and lines 290, 297, 304
- **Severity**: LOW
- **Description**: The auto-search greeting builds the name fallback inline: `(firstName != null && !firstName.isBlank()) ? firstName : "there"`. The same pattern is duplicated in `buildGreeting()`, `buildOutOfScopeGreeting()`, and `buildAmbiguousGreeting()`.
- **Suggestion**: Extract a private `resolveName(String firstName)` helper to eliminate duplication.
